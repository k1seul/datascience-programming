# Week 04 / Python (쉬움) — 합이 정해진 조합

값들 중에서 **`k` 개를 골라 합이 `target` 이 되는** 모든 경우를 찾아 주세요.
Week 03 의 부분집합 과제와 같은 백트래킹 골격에, 조건 두 개가 붙은 형태입니다.

```python
combinations_with_sum([1, 2, 3, 4], 2, 5)
# [[1, 4], [2, 3]]
```

## 구현할 함수

```python
def combinations_with_sum(values: Sequence[int], k: int, target: int) -> list[list[int]]: ...
```

## 조건

- **각 조합 안의 값은 입력에 나온 순서를 유지**해야 합니다.
  `combinations_with_sum([4, 1, 3, 2], 2, 5)` 의 답에는 `[4, 1]` 이 들어갑니다. `[1, 4]` 가 아닙니다.
- **조합들 사이의 순서는 상관없습니다.** 채점기가 정렬해서 비교합니다.
- 같은 값을 두 번 쓸 수 없습니다. 각 자리에서 서로 다른 위치의 값을 골라야 합니다.
- 입력에 중복된 값은 없다고 가정합니다.
- `itertools` 를 쓰지 마세요. 채점기가 소스를 확인합니다.
- 입력을 바꾸지 마세요.

## 경계 처리

여기서 실수하면 통째로 틀립니다. 꼭 확인해 주세요.

| 입력 | 결과 | 이유 |
|---|---|---|
| `k = 0`, `target = 0` | `[[]]` | 아무것도 고르지 않으면 합이 `0` 입니다. 그것도 하나의 답입니다 |
| `k = 0`, `target != 0` | `[]` | 아무것도 안 고르고 `0` 이 아닌 합을 만들 수는 없습니다 |
| `k < 0` | `[]` | |
| `k > len(values)` | `[]` | 있는 것보다 많이 고를 수는 없습니다 |
| 조건을 만족하는 조합이 없음 | `[]` | |

`[[]]` 와 `[]` 의 차이를 조심하세요. 앞은 **답이 하나 있고 그 답이 빈 리스트**,
뒤는 **답이 없음**입니다.

## 예시 몇 개 더

```python
combinations_with_sum([1, 2, 3], 2, 4)       # [[1, 3]]
combinations_with_sum([1, 2, 3], 2, 100)     # []
combinations_with_sum([1, 2, 3], 3, 6)       # [[1, 2, 3]]
combinations_with_sum([5], 1, 5)             # [[5]]
combinations_with_sum([], 0, 0)              # [[]]
combinations_with_sum([-1, 1, 2], 2, 1)      # [[-1, 2]]
```

## 생각해 볼 것

- 값이 모두 양수라면 **가지치기**를 넣을 수 있습니다. 지금까지 고른 합이 이미 `target` 을
  넘었다면 더 들어갈 필요가 없죠. 음수가 섞여 있으면 왜 그 가지치기를 쓸 수 없을까요?
- `k` 개를 다 고르기 전에 값이 모자라는 경우를 미리 알 수 있을까요?
  남은 자리가 3개인데 후보가 2개뿐이면 더 볼 필요가 없습니다. 이 조건을 어떻게 쓸까요?
- `target` 조건을 떼면 그냥 "`k` 개를 고르는 모든 조합" 이 됩니다.
  두 코드의 차이가 몇 줄인지 확인해 보세요.
