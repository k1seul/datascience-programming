# Week 05 / Python (중간) — 분할 매도

여러 계좌에 나뉘어 있는 주식을 정해진 날짜 안에 모두 팔려고 합니다.
하루에 팔 수 있는 양에 **한도**를 둘 때, 기한을 지킬 수 있는 **가장 작은 한도**를 구하세요.

## 문제

`holdings[i]` 는 `i` 번째 계좌에 들어 있는 주식 수입니다. 주식은 다음 규칙으로 팝니다.

- 하루에는 **계좌 하나**에서만 팝니다.
- 그날 그 계좌에서 **최대 `limit` 주**까지 팔 수 있습니다.
- 계좌에 남은 주식이 `limit` 보다 적으면 남은 것만 팔고 그날은 끝납니다.
  **같은 날 다른 계좌로 넘어가서 팔 수는 없습니다.**
- 계좌를 파는 순서는 상관없습니다. 어떤 순서로 팔아도 걸리는 날수는 같습니다.

`days` 일 안에 모든 계좌를 다 비울 수 있는 `limit` 중 **가장 작은 값**을 구하세요.

## 예시

`holdings = [3, 6, 7, 11]`, `days = 8` 일 때 답은 `4` 입니다.

`limit = 4` 로 팔면 이렇게 됩니다.

| 날 | 파는 계좌 | 판 주식 | 그 계좌에 남은 주식 |
|---|---|---|---|
| 1일 | 계좌 0 (3주) | 3 | 0 → 끝 |
| 2일 | 계좌 1 (6주) | 4 | 2 |
| 3일 | 계좌 1 | 2 | 0 → 끝 |
| 4일 | 계좌 2 (7주) | 4 | 3 |
| 5일 | 계좌 2 | 3 | 0 → 끝 |
| 6일 | 계좌 3 (11주) | 4 | 7 |
| 7일 | 계좌 3 | 4 | 3 |
| 8일 | 계좌 3 | 3 | 0 → 끝 |

8일이 걸리니 기한 안에 들어옵니다.

`limit = 3` 이면 계좌마다 1일, 2일, 3일, 4일이 걸려서 모두 **10일**이 필요합니다. 8일을 넘으니 안 됩니다.
그래서 가능한 가장 작은 한도는 `4` 입니다.

다른 예시입니다.

| `holdings` | `days` | 답 | |
|---|---|---|---|
| `[30, 11, 23, 4, 20]` | `5` | `30` | 계좌가 5개, 날도 5일이니 하루에 계좌 하나를 통째로 팔아야 합니다 |
| `[30, 11, 23, 4, 20]` | `6` | `23` | |
| `[5]` | `5` | `1` | 하루에 1주씩 5일 |
| `[7]` | `2` | `4` | 4주 + 3주 |
| `[10, 10]` | `4` | `5` | 계좌마다 5주 + 5주 |
| `[1000]` | `1` | `1000` | |

## 구현할 함수

`solution.py` 에 작성하세요.

```python
def can_sell_all(holdings: Sequence[int], days: int, limit: int) -> bool: ...
def min_daily_limit(holdings: Sequence[int], days: int) -> int: ...
```

| 함수 | 하는 일 |
|---|---|
| `can_sell_all(holdings, days, limit)` | 한도가 `limit` 일 때 `days` 일 안에 다 팔 수 있으면 `True`, 아니면 `False` |
| `min_daily_limit(holdings, days)` | `days` 일 안에 다 팔 수 있는 가장 작은 한도 |

```python
can_sell_all([3, 6, 7, 11], 8, 4)    # True   (8일 필요)
can_sell_all([3, 6, 7, 11], 8, 3)    # False  (10일 필요)
min_daily_limit([3, 6, 7, 11], 8)    # 4
```

## 입력 조건

- `holdings` 의 각 값은 1 이상입니다.
- `days >= len(holdings)` 입니다. 하루에 한 계좌씩 통째로 팔면 되니 **답은 항상 있습니다.**
- 답은 `1` 이상 `max(holdings)` 이하입니다.
- `limit` 이 0 이하이면 `can_sell_all` 은 `False` 를 반환하세요.

## 지켜야 할 것

- `min_daily_limit` 안에서 어떤 한도가 가능한지 확인할 때는 **`can_sell_all` 을 호출**하세요.
  같은 계산을 직접 다시 쓰지 마세요.
- **한도를 1부터 하나씩 늘려 가며 확인하는 방식은 통과하지 못합니다.** 채점기가 `can_sell_all` 이
  몇 번 호출되었는지 셉니다. 답의 범위가 1~1000 일 때 20번 이내로 찾아야 합니다.
- `holdings` 를 수정하지 마세요.

## 자주 하는 실수

**올림 대신 그냥 나누기**

`7 // 4` 는 `1` 입니다. 하지만 7주를 한도 4로 팔려면 2일이 걸립니다. 반드시 올림해야 합니다.

**가능할 때 `mid - 1` 로 줄이기**

`can_sell_all(mid)` 가 `True` 이면 `mid` 자체가 답일 수 있습니다. `hi = mid - 1` 로 줄이면 답을
건너뛸 수 있습니다. `hi = mid` 로 두세요.

**답의 범위를 잘못 잡기**

답은 `0` 이 아니라 `1` 부터입니다. 위쪽 끝은 `max(holdings)` 로 충분합니다. 한도가 가장 큰 계좌보다
크면 어느 계좌든 하루에 끝나니 더 키워도 날수가 줄지 않습니다.
