# Week 05 / C (중간) — 이진 탐색

정렬된 배열에서 값을 찾습니다. 찾는 방법은 간단합니다.

```
가운데를 본다  ->  찾는 값보다 크면 왼쪽만, 작으면 오른쪽만 본다  ->  반복
```

한 번 볼 때마다 후보가 절반으로 줍니다. 100만 개짜리 배열도 스무 번이면 끝납니다.

아이디어는 이렇게 쉬운데 **직접 쓰면 한 칸씩 어긋나기로 유명한** 알고리즘입니다.
이번 과제는 그 경계를 손에 익히는 것이 목적입니다.

## 구현할 함수

```c
int binary_search(const int *values, int n, int target);
int lower_bound(const int *values, int n, int target);
int upper_bound(const int *values, int n, int target);
int count_equal(const int *values, int n, int target);
```

| 함수 | 하는 일 | 반환값 |
|---|---|---|
| `binary_search` | `target` 이 있는 위치 | 그 인덱스, 없으면 `-1` |
| `lower_bound` | `target` **이상**이 처음 나오는 위치 | 인덱스 |
| `upper_bound` | `target` **초과**가 처음 나오는 위치 | 인덱스 |
| `count_equal` | `target` 이 몇 개인지 | 개수 |

입력은 **오름차순으로 정렬되어 있고 같은 값이 여러 번 나올 수 있습니다.**
그래서 "있는 위치" 와 "처음 나오는 위치" 가 다른 질문이 됩니다.

`binary_search` 는 같은 값이 여럿일 때 **그중 아무 위치나** 반환해도 됩니다.
채점기는 `values[결과] == target` 인지만 봅니다. 나머지 셋은 답이 하나뿐입니다.

## 예시로 보면 쉽습니다

```
values = [1, 2, 2, 2, 5]
          0  1  2  3  4     <- 인덱스
```

| `target` | `lower_bound` | `upper_bound` | `count_equal` | |
|---|---|---|---|---|
| `0` | `0` | `0` | `0` | 전부 0보다 크니 맨 앞 |
| `1` | `0` | `1` | `1` | 1은 0번 자리에 하나 |
| `2` | `1` | `4` | `3` | 2는 1·2·3번 자리에 셋 |
| `3` | `4` | `4` | `0` | 3은 없고, 3보다 큰 건 4번 자리부터 |
| `5` | `4` | `5` | `1` | |
| `6` | `5` | `5` | `0` | **6보다 큰 게 없으니 `n`(=5)** |

마지막 행이 헷갈리는 지점입니다. **찾는 값보다 큰 것이 없으면 `n` 을 반환합니다.**
배열 밖의 인덱스지만 "그 뒤로는 없다"는 뜻으로 쓰는 관례이고, `-1` 대신 `n` 을 쓰는 덕분에
`count_equal` 을 간단하게 만들 수 있습니다.

표의 `upper_bound` 열에서 `lower_bound` 열을 빼 보세요. `count_equal` 열이 나옵니다.

## 조건

- `values` 는 이미 정렬되어 있습니다. 직접 정렬하지 마세요.
- **`O(log n)` 으로 풀어 주세요.** 처음부터 하나씩 비교하면 답은 맞지만 이 과제의
  목적에서 벗어납니다.
- `bsearch`(C 표준 라이브러리)를 쓰지 마세요. 채점기가 소스를 확인합니다.
- 반복문과 재귀 **둘 다 괜찮습니다.** 이진 탐색의 핵심은 경계 논리이고, 실무에서는
  반복문으로 쓰는 쪽이 보통입니다.
- `n = 0` 인 빈 배열도 처리해야 합니다. 네 함수 모두 `0` 또는 `-1` 을 돌려주면 됩니다.

## 경계는 짝으로 외우세요

섞어 쓰면 무한 루프가 나거나 답을 한 칸 지나칩니다. 한 가지를 골라 통째로 기억하는 게
가장 안전합니다.

```c
/* 이 조합을 권합니다 */
int lo = 0, hi = n;              /* hi 는 "아직 모르는 구간의 끝 다음" */
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (조건) hi = mid;          /* mid 도 후보로 남긴다 */
    else      lo = mid + 1;      /* mid 는 확실히 아니다 */
}
return lo;                       /* lo == hi 가 답 */
```

`lower_bound` 와 `upper_bound` 는 위 코드에서 **`조건` 하나만 다릅니다.**
`values[mid] >= target` 인지 `values[mid] > target` 인지요.

## 가운데를 구할 때

```c
int mid = (lo + hi) / 2;          /* 위험합니다 */
int mid = lo + (hi - lo) / 2;     /* 이렇게 쓰세요 */
```

`lo` 와 `hi` 가 모두 20억에 가까우면 `lo + hi` 가 `int` 범위를 넘어 음수가 됩니다.
그러면 `mid` 가 배열 밖을 가리키죠. 지금 테스트에서는 드러나지 않지만 실제로 큰 데이터를
다루면 터지는, 이름까지 붙은 유명한 버그입니다.
