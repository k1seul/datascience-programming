# Week 05 / C (중간) — 체결 기록에서 구간 찾기

체결 기록이 **시각 순으로 정렬**되어 들어옵니다. 여기서 원하는 구간을 잘라 내는 함수들을
만듭니다. 시계열 데이터를 다룰 때 가장 자주 하는 일이고, 데이터가 많아지면 처음부터
하나하나 보는 방식으로는 감당이 안 됩니다.

```
ts = [100, 200, 200, 200, 500]
       0    1    2    3    4     <- 인덱스

200 이상이 처음 나오는 곳?   ->  1
200 초과가 처음 나오는 곳?   ->  4
200 에 체결된 건수?          ->  3
```

같은 시각에 여러 건이 체결될 수 있어서 **중복된 값이 들어옵니다.** 이 과제의 난이도는
거기서 나옵니다.

## 구현할 함수

`search.h` 에 선언되어 있습니다.

```c
int find_trade(const int *ts, int n, int t);
int first_at_or_after(const int *ts, int n, int t);
int first_after(const int *ts, int n, int t);
int count_in_range(const int *ts, int n, int lo, int hi);
```

| 함수 | 하는 일 | 반환값 |
|---|---|---|
| `find_trade` | 시각이 정확히 `t` 인 체결 하나 | 그 인덱스, 없으면 `-1` |
| `first_at_or_after` | 시각이 `t` **이상**이 처음 나오는 위치 | 인덱스, 전부 `t` 미만이면 `n` |
| `first_after` | 시각이 `t` **초과**가 처음 나오는 위치 | 인덱스, 전부 `t` 이하면 `n` |
| `count_in_range` | `lo <= 시각 <= hi` 인 건수 | 개수, `lo > hi` 면 `0` |

`find_trade` 는 같은 시각이 여럿일 때 **그중 아무 위치나** 반환해도 됩니다.
채점기는 `ts[결과] == t` 인지만 확인합니다. 나머지 셋은 답이 하나뿐입니다.

## 헷갈리는 경우를 미리 정리합니다

`ts = [100, 200, 200, 200, 500]` 일 때,

| `t` | `first_at_or_after` | `first_after` |
|---|---|---|
| `0` | `0` | `0` |
| `100` | `0` | `1` |
| `200` | `1` | `4` |
| `300` | `4` | `4` |
| `500` | `4` | `5` |
| `600` | `5` | `5` |

마지막 두 행이 핵심입니다. **찾는 값보다 큰 것이 없으면 `n` 을 반환합니다.**
배열 밖의 인덱스지만, "그 뒤로는 없다"는 뜻으로 쓰는 관례입니다.
`n` 대신 `-1` 을 반환하면 `count_in_range` 를 만들 때 곤란해집니다.

## 조건

- `ts` 는 오름차순으로 정렬되어 있습니다. 직접 정렬하지 마세요.
- **`O(log n)` 으로 풀어 주세요.** 처음부터 하나씩 비교하면 답은 맞지만 이 과제의 목적에서
  벗어납니다. 체결 기록이 하루에 수천만 건인 것을 생각해 보세요.
- `bsearch`(C 표준 라이브러리)를 쓰지 마세요. 채점기가 소스를 확인합니다.
- 반복문과 재귀 **둘 다 괜찮습니다.** 이진 탐색의 핵심은 경계 논리이고, 실무에서는
  반복문으로 쓰는 쪽이 보통입니다.
- `n = 0` 인 빈 기록도 처리해야 합니다.

## 가운데를 구할 때

```c
int mid = (lo + hi) / 2;          /* 위험합니다 */
int mid = lo + (hi - lo) / 2;     /* 이렇게 쓰세요 */
```

`lo` 와 `hi` 가 모두 20억에 가까우면 `lo + hi` 가 `int` 범위를 넘어 음수가 됩니다.
그러면 `mid` 가 배열 밖을 가리키죠. 지금 테스트에서는 드러나지 않지만,
실제로 큰 데이터를 다루면 터집니다. 유명한 버그라 이름까지 붙어 있습니다.
