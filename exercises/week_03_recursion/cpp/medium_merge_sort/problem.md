# Week 03 / C++ (중간) — 재귀 머지 소트

정수 배열을 오름차순으로 정렬해 주세요. 단, **머지 소트를 직접 구현**해야 합니다.

```
[5, 2, 9, 1, 5, 6]  ->  [1, 2, 5, 5, 6, 9]
[]                  ->  []
[3]                 ->  [3]
```

## 시그니처

```cpp
extern "C" int merge_sort(const int *values, int n, int *out, int out_capacity);
```

- 입력 `values` 는 바꾸지 마세요 (`const` 입니다). 결과는 `out` 에 씁니다.
- 반환값은 `out` 에 쓴 개수(`n`)입니다. `out_capacity` 가 `n` 보다 작으면 `-1` 입니다.
- `n >= 0` 이고, 빈 배열이면 아무것도 쓰지 않고 `0` 을 반환합니다.

## 조건

- **`std::sort`, `std::stable_sort`, `qsort` 를 쓰지 마세요.** 채점기가 소스를 확인합니다.
  이번 과제는 정렬된 결과가 아니라 **머지 소트를 짜는 것**이 목적입니다.
- 분할 정복으로 풀어 주세요. 배열을 반으로 나눠 각각 정렬하고, 정렬된 두 조각을 합칩니다.
- 중복된 값이 있어도 동작해야 하고, 음수도 들어옵니다.

## 머지 소트의 모양

```
정렬(구간):
    구간의 길이가 1 이하면 이미 정렬된 것이다      <- 기저 조건
    가운데를 기준으로 왼쪽과 오른쪽을 각각 정렬한다  <- 재귀
    정렬된 두 조각을 앞에서부터 비교하며 합친다      <- 병합
```

**병합이 이 과제의 실제 일감입니다.** 두 조각을 합치려면 결과를 담을 자리가 따로 필요합니다.
제자리에서 섞으려고 하면 아직 안 쓴 값을 덮어쓰게 됩니다.
임시 버퍼를 한 번만 잡아서 재귀 내내 돌려쓰는 방법을 생각해 보세요.

## 생각해 볼 것

- 재귀 깊이는 얼마인가요? 매번 절반으로 나누니 `n` 이 100만이어도 깊이가 얼마 되지 않습니다.
  만약 절반이 아니라 **매번 1개만 떼어 낸다면** 깊이가 어떻게 될까요?
  그때 `n` 이 100만이면 무슨 일이 생길까요? (C 와 C++ 에서는 경고 없이 죽습니다.)
- 임시 버퍼를 재귀 호출마다 새로 잡으면 무엇이 문제일까요?
- 병합할 때 두 조각에 같은 값이 있으면 어느 쪽을 먼저 가져와야 할까요?
  정수만 다루는 지금은 차이가 없지만, 값에 딸린 다른 정보가 있다면 달라집니다.
  이것을 정렬의 **안정성(stability)** 이라고 부릅니다.
