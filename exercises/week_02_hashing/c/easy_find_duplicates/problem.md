# Week 02 / C (쉬움) — `0~99` 에서 중복 찾기

0 이상 99 이하의 정수가 담긴 배열이 주어집니다. 여기서 중복을 찾는 함수 세 개를 만듭니다.

```
[3, 1, 4, 1, 5]        -> 중복 있음, 처음 중복된 값은 1, 중복 목록은 [1]
[7, 7, 2, 2, 2, 9]     -> 중복 목록은 [2, 7]
[1, 2, 3]              -> 중복 없음
```

## 시그니처

```c
int has_duplicate(const int *values, int n);
int first_duplicate(const int *values, int n);
int find_duplicates(const int *values, int n, int *out, int out_capacity);
```

| 함수 | 하는 일 | 반환값 |
|---|---|---|
| `has_duplicate` | 중복이 하나라도 있는지 | 있으면 `1`, 없으면 `0`, 범위 밖 값이 있으면 `-1` |
| `first_duplicate` | **두 번째로 등장하는 순간이 가장 이른** 값 | 그 값, 중복이 없으면 `-1`, 범위 밖이면 `-2` |
| `find_duplicates` | 두 번 이상 나온 값들을 **오름차순**으로 `out` 에 | 개수, 용량 부족이면 `-1`, 범위 밖이면 `-2` |

`first_duplicate` 의 기준을 헷갈리지 마세요. 가장 작은 값도, 가장 먼저 나온 값도 아니고
**두 번째 등장이 가장 빠른** 값입니다.

```
[5, 3, 5, 3]   ->  5    (5 의 두 번째 등장이 인덱스 2, 3 은 인덱스 3)
[3, 5, 3, 5]   ->  3
```

## 조건

- `n >= 0` 입니다. 빈 배열도 처리해야 합니다.
- 값이 `0~99` 범위를 벗어나면 위 표대로 오류를 반환합니다.
  **인덱스로 쓰기 전에 검사해야 합니다.** 검사 없이 `seen[values[i]]` 를 쓰면
  값이 150 일 때 배열 밖을 건드립니다.
- **범위 검사가 가장 우선입니다.** 배열 어딘가에 범위 밖 값이 하나라도 있으면,
  그 앞에서 중복을 이미 찾았더라도 오류를 반환합니다.
  `find_duplicates` 에서 용량도 모자라고 범위 밖 값도 있다면 범위 오류(`-2`)가 먼저입니다.
- 정렬하지 마세요. 입력 배열은 한 번만 훑으면 됩니다.
  `find_duplicates` 는 그 뒤에 100칸짜리 표를 한 번 더 훑어 결과를 만듭니다.

## 힌트

값이 `0~99` 로 정해져 있으니 100칸짜리 배열 하나면 충분합니다.

```c
int seen[100] = {0};
seen[values[i]]++;      /* 값이 곧 인덱스 */
```

## 생각해 볼 것

- 위의 `seen[100]` 은 사실 **해시 테이블**입니다. 해시 함수가 `hash(x) = x` 이고
  충돌이 절대 일어나지 않는 특별한 경우죠. 왜 충돌이 없을까요?
- `find_duplicates` 의 결과는 정렬을 하지 않았는데도 오름차순으로 나옵니다. 왜 그럴까요?
- 값의 범위가 `0~99` 가 아니라 `0~1,000,000,000` 이라면 이 방법은 어떻게 될까요?
  배열을 얼마나 잡아야 하고, 그중 몇 칸이나 실제로 쓰일까요?
- 값이 정수가 아니라 문자열이라면 무엇을 인덱스로 쓸 수 있을까요?

마지막 두 질문이 진짜 해시 함수와 충돌 처리가 필요한 이유입니다. 지금 답을 내지 못해도 괜찮습니다.
